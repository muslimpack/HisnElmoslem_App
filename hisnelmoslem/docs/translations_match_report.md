## How matching works

- **Text signal**: normalised Arabic of the app zikr (Quran placeholders expanded, diacritics and honorifics removed) against `HSN_Ar` (ZekarText and OrgZekarText), the title's own the source DB category first: same text (exact >= 0.98, near >= 0.85), the app zikr inside one item (partial), several items inside the app zikr (combined), one item inside a longer app zikr with narration (near).
- **Number signal**: app zikr -> binwahaf lesson (`tools/binwahaf_out`) -> book hadith number N -> hisnmuslim item N (`tools/translations_raw`) -> the source DB zikr. The last hop compares the source DB with the hisnmuslim files (Arabic and English) only, never with the app text.
- **ZekarID is not the hadith number**: it equals the hisnmuslim id up to about 113, then drifts (+5 and more). the source DB also holds Arabic-only items: the evening copies (category 135) and pieces of translated items (ids above 275). Each is mapped to the translated item that carries it.
- **Confidence**: high = both signals land on the same the source DB zikr; medium = only one signal exists (no binwahaf lesson) or the number signal is supported by word overlap; manual = `tools/translations_overrides.json`.
